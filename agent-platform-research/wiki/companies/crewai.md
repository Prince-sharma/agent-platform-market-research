## The eleven build decisions

1. **Build interface:** No-code visual canvas and code-first Python API
2. **Runtime and tenancy:** Vendor multi-tenant SaaS (Enterprise console) and local development
3. **Tool and integration strategy:** Integration toolkit for Gmail, Slack, Salesforce, and Amazon Bedrock Agents
4. **Knowledge and data strategy:** Built-in memory and knowledge capabilities
5. **Autonomy and human-in-the-loop:** Human-in-the-loop approval gates and intervention during execution
6. **Governance and enterprise controls:** RBAC, immutable audit trails, Enterprise IAM, and PII redaction hooks
7. **Pricing model:** unknown
8. **GTM motion:** PLG self-serve (OSS) and sales-led (Enterprise)
9. **Moat thesis:** Workflow lock-in via 700k agent workflow patterns and broad OSS adoption
10. **Open-source posture:** OSS core; Enterprise build and run layer
11. **Task horizon:** Long-horizon (hours to weeks) via persistent flows and state management

## Analysis

- **Agent capability depth:** Orchestrates role-based teams to automate complex operational work, including lead enrichment, curriculum design, and customer support.
- **Weaknesses:** Pricing transparency is missing from public documentation.
- **Trajectory:** Rapidly transitioning from a developer framework to a full enterprise platform with a dedicated control plane.
- **M&A:** none visible
