## The eleven build decisions

1. **Build interface:** code / config workflow
2. **Runtime and tenancy:** vendor multi-tenant SaaS (LlamaCloud) / self-host (OSS)
3. **Tool and integration strategy:** MCP (Model Context Protocol) and LlamaHub connector library
4. **Knowledge and data strategy:** built-in RAG with LlamaParse for document OCR and indexing
5. **Autonomy and human-in-the-loop:** approval gates; guardrails
6. **Governance and enterprise controls:** RBAC, data encryption, HIPAA compliance
7. **Pricing model:** platform fee plus usage (credits)
8. **GTM motion:** PLG self-serve
9. **Moat thesis:** integrations and document parsing accuracy (LlamaParse)
10. **Open-source posture:** OSS core; self-host option (LiteParse)
11. **Task horizon:** multi-step workflow (minutes)

## Analysis

- **Agent capability depth:** End-to-end document agents that parse complex layouts (OCR), extract structured data via schemas, and execute multi-step knowledge work.
- **Weaknesses:** Heavy reliance on developer-centric code implementation for complex agentic workflows.
- **Trajectory:** Expanding from a developer framework into a full-stack data pipeline platform via LlamaCloud and LlamaParse.
